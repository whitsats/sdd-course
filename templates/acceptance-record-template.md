## 元验证：证明「测试真的能抓到问题」

> **本节的目的：证明你的验证过程本身是有效的，而不是走过场。**
>
> 方法：**故意破坏一个东西，确认它真的被发现。**

| 破坏动作 | 期望看到的 | 实际看到的 |
|---------|-----------|-----------|
| 故意写一条会失败的测试 | 它确实失败 | |
| 故意违反一条规格（改代码不改规格） | 门禁变红 | |
| 故意删掉一条映射行 | 覆盖率门禁变红 | |

> ⛔ **没有做过元验证的验收记录，可信度有限。**
> 一个「全部通过」的结果，可能是系统正确，也可能是**检查根本没在工作**。
> 两者在输出上完全一样 —— 这就是为什么必须做元验证。
