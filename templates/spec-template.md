## 3. 验收标准（EARS 句式）

> **本节是规格的核心。** 每一行都会被映射到测试。
>
> 句式速查见 `reference/ears.md`。五种句式：
> - **普遍**：THE system SHALL …
> - **事件**：WHEN … THE system SHALL …
> - **状态**：WHILE … THE system SHALL …
> - **条件**：IF … THEN THE system SHALL …
> - **不期望**：IF … THEN THE system SHALL NOT …

### US-1 <故事名>

- WHEN <触发条件> THE system SHALL <可观测的行为>。
- IF <前提> THEN THE system SHALL <行为>。
- THE system SHALL <始终成立的性质>。

### US-2 <故事名>

- WHEN …

### 每条标准的可测性自查

对每条标准问三句：

| 检查 | 不合格的样子 | 合格的样子 |
|------|-------------|-----------|
| **可观测吗** | 「用户体验流畅」 | 「首屏在 1s 内出现首条内容」 |
| **可判定吗** | 「尽量快」 | 「95 分位 < 200ms」 |
| **有边界吗** | 「支持大文件」 | 「≤ 100MB 的文件能上传；> 100MB 返回 413」 |

> ⛔ **出现「友好」「合理」「尽快」「适当」「可能」这类词，就是没写完。**
> 它们不是标准，是标准的占位符。见 `reference/anti-patterns.md` AP-07。

## 4. 六类歧义区（写完自检）

> **这六处是规格歧义的高发区。** 每处都要显式给一个答案（或显式声明「本期不涉及」）。
> 这是 `/speckit-clarify` 会追问的方向。

| 歧义区 | 本规格的答案 |
|--------|------------|
| **① 边界与极值**（空、零、最大、负数、超长） | |
| **② 错误与失败**（谁看到什么、可以重试吗） | |
| **③ 权限与可见性**（谁不能做什么） | |
| **④ 并发与顺序**（同时发生怎么办、乱序怎么办） | |
| **⑤ 时间与时效**（时区、时钟、有效期） | |
| **⑥ 状态转换**（哪些转换合法、非法转换怎么处理） | |

**留空的格子就是将来返工的地方。**
