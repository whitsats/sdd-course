# 澄清记录 · <feature 名>

> 位置：`specs/<NNN>-<feature-name>/clarify.md`（或并入 `spec.md` 的澄清章节）
> 触发方式：`/speckit-clarify`，或人工在评审时提问
>
> **本文件回答一个问题：我们当时为什么这么理解这条规格？**

---

## 为什么值得单独留一份记录

**规格只记录「结论」，不记录「当初的假设」。**

而假设是会失效的。当规格需要修改时，唯一能判断
「这条还成立吗」的材料，就是这个文件 —— 它写着：

- 当时有哪些选项
- 为什么排除了其他选项
- 这个选择依赖了什么前提

> 📌 **一个具体的例子**：
> 某条标准选择「同步返回结果」而不是「异步 + 回调」，
> 理由是「单次处理 < 100ms」。
> 半年后数据量涨了 50 倍 ——
> **有澄清记录，一眼就看出这条权衡已失效；没有它，只能重新讨论一遍。**

## 通用澄清条目格式

### Q<N> · <一句话问题>

**提出者**：<名字>　**日期**：YYYY-MM-DD
**类别**：歧义 / 边界 / 权限 / 并发 / 时间 / 状态转换

**问题**

> 把问题写成**一个具体的场景**，不要写成抽象疑问。
>
> ⛔ 差的写法：「这里要处理并发吗？」
> ✅ 好的写法：「两个用户在同一秒内把同一任务从 `todo` 改到 `doing`，
> 都读到旧状态，两个都写入 —— 结果是两条 `doing` 记录还是后来者覆盖？」

**选项**

| 选项 | 行为 | 优点 | 缺点 |
|------|------|------|------|
| A | | | |
| B | | | |
| C 什么都不做 | | | |

**选择**：<A>

**理由**：<具体，可被反驳>

**依赖的前提**（将来什么变了这条就要重新讨论）：

- <例：任务数量 < 1000>
- <例：团队没有跨时区协作>

## 六类歧义区的澄清清单

> **逐格填。留空的格子就是将来返工的地方。**
> 「本期不涉及」也是有效答案 —— **留空不是。**

### ① 边界与极值

| 问题 | 答案 | 落到哪条标准 |
|------|------|------------|
| 输入为空时？ | | |
| 输入为 0 / 负数时？ | | |
| 输入为最大值时？ | | |
| 超过上限时怎么报错？ | | |
| 超长字符串 / 超大文件？ | | |

### ② 错误与失败

| 问题 | 答案 | 落到哪条标准 |
|------|------|------------|
| 依赖失败时谁看到什么？ | | |
| 可以重试吗？重试几次？ | | |
| 部分成功怎么办？ | | |
| 错误信息里要不要包含内部细节？ | | |

### ③ 权限与可见性

| 问题 | 答案 | 落到哪条标准 |
|------|------|------------|
| 谁**不能**做这件事？ | | |
| 越权时返回「无权限」还是「不存在」？ | | |
| 看不到的数据能否通过计数/排序推断出来？ | | |

> 📌 **第三行最常被跳过，而它是真实的泄露渠道**：
> 如果「无权限」和「不存在」返回不同的错误，攻击者就能枚举出存在哪些资源。

### ④ 并发与顺序

| 问题 | 答案 | 落到哪条标准 |
|------|------|------------|
| 两个请求同时修改同一条数据？ | | |
| 乱序到达的事件怎么处理？ | | |
| 重复提交（用户狂点按钮）？ | | |
| 冲突时谁赢？用什么机制？ | | |

### ⑤ 时间与时效

| 问题 | 答案 | 落到哪条标准 |
|------|------|------------|
| 用哪个时区？ | | |
| 「今天/本周」按谁的时间算？ | | |
| 跨边界（跨天/跨周/跨月）的数据归属？ | | |
| 依赖系统时钟吗？时钟回拨会怎样？ | | |

> 📌 **跨边界归属这一行是本课程真实抓到过 bug 的地方。**
> `focuslog` 的「跨天会话计入开始日」与「周报排除活跃会话」两条标准叠加后，
> 产生了「会话在周报里凭空消失」的场景 —— 见 `examples/focuslog/notes/L06-LLM审阅记录.md`。
> **这类缺口必须靠「把两条标准放进同一场景」才能发现。**

## 小结

| 项 | 值 |
|----|-----|
| 澄清条目数 | |
| 因澄清而新增的验收标准 | |
| 因澄清而**删除**的验收标准 | |
| 因澄清而发现了**矛盾**的标准 | |

> **最后两行值得认真填。** 澄清如果只产出「新增标准」，
> 说明它只在前推，没有在**收缩**范围 —— 而收缩往往更有价值。
